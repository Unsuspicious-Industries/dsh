# Agent Note：项目携带用户标题，绝不使用文件系统路径

Status: implemented

[English](2026-09-21-projects-carry-user-titles-never-paths.md) | 中文

## 问题

会话浏览器会用该会话工作目录的基名，为不属于任何项目的会话打标签。`workspaceLabel(cwd)` 切分路径并返回最后一段，而 `deriveSearchResults` 把它当作所有不在工作区成员映射中的会话的兜底值。

在工作主机上，这会用偶然的目录凭空造出项目名。侧边栏本应显示用户自己的项目，结果却为智能体运行过的每个路径各显示一个分组：`/workspace`、`/root`、`/tmp`、`/etc/nixos/servers`、`/tmp/v41try`。这些都不是任何人创建的项目。用户的抱怨是字面意义的：侧边栏里排着一串奇怪的文件夹。

这个缺陷是命名决策，不是存储决策。项目只通过 `workspace.create` RPC 创建，GUI 从显式的创建流程调用它。没有任何代码会从 cwd 自动创建项目；只是展示层把一个路径**渲染**得仿佛它是项目，从而使一个隐式分组与用户创建的项目无法区分。

## 决策

一行的项目标签只来自已存储的项目标题。不属于任何项目的会话携带「未分组」标签。

`workspaceLabel` 及其路径解析被删除。`deriveSearchResults` 回退到 `UNGROUPED_LABEL` —— 与 `groupByWorkspace` 中命名未分组分组的同一个常量 —— 因此搜索结果与分组行现在以相同方式命名项目。

未分组分组保留：会话确实可能在任何项目之外运行，它们仍需要一个归处。被移除的是「其目录就是项目」这一假象。

## 后果

侧边栏不再能显示用户未创建的项目，因此任何路径都不会泄漏为项目名。在 `/root/server-work` 中启动的会话现在报告 `Ungrouped`，而看到项目名的唯一方式就是创建过该项目。

有两个调用方依赖被移除的行为，并在同一变更中更新：`deriveSearchResults` 中合并顺序的断言此前期望路径派生标签为 `workspace: 'c'`，`workspaceLabel` 的单元测试块此前断言 POSIX 与 Windows 基名抽取。

`EmptyHero` 的 `workspaceLabel` 是另一个包中的另一个函数，被有意保持不变：它为新会话欢迎页中用户显式选择的目录打标签，那里显示所选目录正是重点。本记录不涉及它。

## 考虑过的替代方案

**保留路径标签，但作为次要文本渲染。** 否决：侧边栏已经显示会话自身的标题，每行再出现一个路径派生字符串，等于用更小的字体重新制造那堆杂乱。需求是停止凭空造项目，而不是给它们换标签。

**首次出现某个 cwd 时自动创建一个真实项目，然后用生成的名称隐藏路径。** 直接按「项目由用户创建」的要求否决。生成的名称也不稳定——目录改名后同一项目会得到不同的名字。

**在组件中过滤形如路径的标签。** 否决：这会把决策放在展示层，`deriveSearchResults` 的第二个消费者不会继承它。标签的归属方是派生逻辑，因此回退值在那里改变。

## 测试

`packages/client/ui-workspace/tests/tree.client.spec.ts` 直接覆盖新行为：一个位于 `/root/server-work` 且不属于任何项目的会话，在搜索结果中标记为 `Ungrouped`；而一个由标题为 `Demo Project` 的项目拥有的会话报告该标题。路径基名永不出现。
