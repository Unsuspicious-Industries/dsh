# Agent Note：移除会话浏览器中自动创建的项目

Status: proposed

[English](2026-09-15-remove-auto-created-projects.md) | 中文

## Problem

工作区注册表在首次启动时为每个会话 `cwd` 自动创建一个项目。bootstrap 会按历史会话记录中的工作目录分组，为每个目录写入一条记录，标题取 `basename(path)`。在已部署实例上，这产生了七个文件夹分区——`/workspace`（41 个会话）、`/root`（27）、`/tmp`（13）、`/etc/nixos/servers`（3）、`/tmp/v41try`（3）、`/root/server-work`（2）、`/workspace/deepseek-harness`（1）——其中没有一个由用户创建或需要。一个会话恰好启动所在的目录不是工作单元：`/tmp` 和临时检出目录只是偶然产物，而分区列表会随每个新路径增长。

同一推导还代替用户决定了会话归属：`cwd` 匹配某条记录的历史会话会被自动收进该项目。两种效应都源于把文件系统路径当作项目身份，而对于一个应由用户主导的功能，这是错误的键。

## Proposal

`WorkspaceRegistry.bootstrap()` 不再推导项目。它只把注册表标记为已初始化，并保持顺序与归属不变；不属于任何项目的历史会话仍可在会话浏览器中访问，而不是被归档到某处。仅为该推导服务的分组机制（`BootstrapGroup`、`compareHeaders`、`sessionSameIds`）随之删除。

`workspaceDomainSpec.version` 由 `2` 升至 `3`。由旧 bootstrap 写入的注册表在打开时被拒绝，而不是迁移——这正是删除得以彻底的原因：七个既有记录无法再次出现。版本变更不影响会话日志：目录不再是分区，而会话仍然保留。

随后部署方从 `services/dsh/default.nix` 一次性删除新版本不再拥有的两个文件：`storages/workspace.json` 与 `storages/session_projcache.json`，以带版本号的标记文件为守卫，并放在 `/root/.dsh` 播种步骤之后，避免陈旧文件被重新复制进来。`sessions/`、`settings.yaml`、`credentials.env` 与 `profiles/` 绝不被触碰。

会话浏览器继续渲染无归属会话：`WorkspaceBrowser.tsx` 已将它们归入未分组账户，因此注册表为空时会在同一列表中显示全部会话，而不是空白面板。这是本次变更交付的状态；用扁平的实时列表取代未分组分区属于后续工作。

## Alternatives considered

- **把既有记录迁移为用户创建的项目。** 它们全部由路径自动生成，没有任何需要保留的内容。迁移只会把杂物换个名字继续携带，并且还需要为每个会话决定归入七个中的哪一个。
- **保留该推导，但把其记录标记为隐藏。** 仍会留下持久状态、身份混淆和 bootstrap 读取逻辑；浏览器将不得不永久区分两类项目。
- **只删除文件，不做版本提升。** 仍可解析的注册表可能被重新播种，bootstrap 会在下次启动时重建同样的记录。
- **保留 `path` 作为项目身份，另加用户命名标签。** 一个实体两个键，而且两个项目仍然无法共用同一目录，而这是合理的需求。

## Acceptance criteria

- 在未定义任何项目时，每个会话仍在会话浏览器中以单一列表可见。
- 标记为版本 2 的注册表在打开时以版本不匹配错误被拒绝；有测试对此断言。
- bootstrap 不写入任何项目行：存在会话且无归属时，`list()` 返回空，存储状态记录 `initialized` 且顺序为空。
- 既有项目不会被共享其目录的历史会话静默加入。
- 落地本次变更的部署完成后，`storages/workspace.json` 与 `storages/session_projcache.json` 不再存在，而 `sessions/` 与 `settings.yaml` 保持完好。

## Risks

- 本次变更移除了对近期会话的即时隐藏能力：可见性改为由时间与星标推导，因此会话在自然过期前无法被手动收起。这是有意的取舍，也是实时列表后续工作的主题。
- 拒绝旧格式意味着在改造前的注册表中确实建立过项目的用户会失去它们。在本实例上所有记录都是机器生成的，这才使版本提升无需代价；换到其他实例则不然。
- 无归属会话在单列表中是无界的，而分组时并非如此：目前尚无机制在该列表中区分近期与陈旧，因此在实时/归档拆分落地前，列表长度等于既有的会话总数。
- 若另一个进程在清理期间仍持有该注册表，可能会重写被删除的文件。状态准备单元在同一次系统激活中先于 Web 单元运行，因此不会有旧进程存活到那时。
